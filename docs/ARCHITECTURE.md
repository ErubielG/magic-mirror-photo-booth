# System architecture

The 40-inch LCD panel is driven by an M.NT68676.3 LVDS controller replacing the original MIR63A0 board. Raspberry Pi 4 supplies HDMI video; a Sony IMX708 connects over CSI-2. The existing MEGMEET PSU supplies 12 V to the controller and 24 V to the backlight; a buck converter provides 5 V for the Pi. **Verify all actual harness pinouts before servicing powered hardware.**

The Pi hosts Flask and a local NetworkManager shared-mode Wi-Fi access point. Guests use a QR code and browser without venue internet. The mirror and phone pages are separate interfaces to shared application state. Guest visits persist independently of short mirror ownership.

**Direct printing used at the November 14 event:** A guest could select up to four photographs and request one vertical 4×6-inch sheet per visit. The Raspberry Pi validated session ownership and sheet limits, composed the output, queued the request, and submitted it automatically through Linux CUPS with `lp -d selphy`. The Canon SELPHY CP1500 was connected to the PhotoBooth Wi-Fi access point before the event. With **manual printing and per-sheet approval both disabled**, the queue printed without an operator, intermediary phone, or `/admin` approval. The same automatic CUPS path had also been tested during development against a virtual PDF printer (`cups-pdf`).

**Versions and optional modes:** The system initially ran booth19; booth20 was installed during setup and arrival of the first guests, and continued operating autonomously for the rest of the evening. The source also retains optional per-sheet approval and manual download/Canon-app printing modes, neither of which was used for event printing. Reported consumption of approximately 30–40 photo sheets is an estimate, not an independently logged print-total metric.
